# Материалы

Команды, создающие конструктивные элементы, показывают модальный диалог **«Выбор материала для: &lt;тип элемента&gt;»** перед запросом размеров.

## Как формируется список

Диалог сканирует **все открытые документы САПФИР**:

1. Перебираются документы `GetDocByID(1…100)`, затем проекты (`CountProjects`), этажи (`CountStorey`) и модели этажа (`CountModel`).
2. Отбираются модели, у которых `TypeModel` равен **251** или **252** (модели материалов САПФИР).
3. Из каждой такой модели читаются параметры:
   - `M_GUID` — идентификатор материала;
   - `M_NAME` — имя материала.
4. Дубликаты по GUID отбрасываются.

В шапке диалога выводится количество найденных материалов: `Материалов: N`.

## Если материалы не найдены

Когда ни одной модели с типом 251/252 в документах нет (например, проект пустой), подставляется **встроенный список из 5 материалов**:

| GUID | Имя |
|---|---|
| `ab7d2fa2-df44-4d8f-8d46-71b7fb919bde` | Бетон тяжёлый (стена) |
| `79f404bd-50e9-4058-b664-c159ffdd0ce8` | Бетон тяжёлый (плита) |
| `239d15bb-4253-4546-89f1-2d90300a3c79` | Бетон тяжёлый (фундамент) |
| `bf0bce6b-c444-4d27-9b90-d0a38b6870b7` | Железобетон (колонна) |
| `25304e6e-8203-4968-b6fb-22b82250b55c` | Железобетон балок |

В шапке диалога при этом выводится: `Встроенные материалы (5)`.

!!! tip "Как получить полноценный список"
    Создайте (или импортируйте) в проекте САПФИР хотя бы один материал — после этого диалог будет показывать материалы **из проекта**, а не встроенный список.

## Кнопки диалога

| Кнопка | Действие |
|---|---|
| **OK** | активируется после выбора строки; записывает GUID и имя материала, печатает `Материал: <Имя>` |
| **Пропустить (по умолчанию)** (или закрытие окна) | материал не выбран; поведение зависит от команды — см. таблицу ниже |
| двойной клик по строке | равноценен нажатию **OK** |

## Что происходит при пропуске выбора

| Команда | Тип модели | Материал при пропуске |
|---|---|---|
| [`Sapfir_WALLS`](../commands/walls.md#sapfir_walls) | `TM_WALL` | `ab7d2fa2-…` — Бетон тяжёлый (стена), записывается в `M_MATERIAL` |
| [`Sapfir_SLABS`](../commands/slabs.md#sapfir_slabs) | `TM_SLAB` | `79f404bd-…` — Бетон тяжёлый (плита) |
| [`Sapfir_Found_SLABS`](../commands/slabs.md#sapfir_found_slabs) | `TM_SLAB_1` | `239d15bb-…` — Бетон тяжёлый (фундамент) |
| [`Sapfir_COLUMNS`](../commands/columns.md) | `TM_COLUMN` | **ничего** — `M_MATERIAL` не задаётся, материал остаётся назначенным в САПФИР |
| [`Sapfir_BEAMS`](../commands/beams.md) | `TM_BEAM` | **ничего** — `M_MATERIAL` не задаётся |

Также материал не запрашивается у команд осей, нагрузок, линий построения и проёмов.

## Как материал попадает в модель

Внутри создаётся параметр модели с GUID строкой:

```csharp
paramModelSpf.Parameter["M_MATERIAL"] = selectedMaterialGuid;   // например, ab7d2fa2-…
```

Поэтому в САПФИР материал подставляется **по GUID** — имя служит только для отображения в диалоге.

## Диагностика

| Симптом | Причина |
|---|---|
| Список пуст, показан встроенный набор из 5 | в открытых проектах нет моделей материалов (типы 251/252) |
| Диалог долго открывается | сканирование всех открытых документов/проектов/этажей/моделей — на больших проектах это заметно |
| Материал не применился | команда относится к тем, кто не пишет `M_MATERIAL` при пропуске (`Sapfir_COLUMNS`, `Sapfir_BEAMS`) |
