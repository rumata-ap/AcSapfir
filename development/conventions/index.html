    Язык и платформа¶

    • C# для .NET Framework 4.8; допустимы конструкции C# 7 (pattern matching is T t, out var, кортежи, локальные функции).
    • Пространство имён — AcSapfir; один класс — один файл, имя файла = имя класса (исключение — перечисления в конце SapfirDrafter.cs).
    • UI-строки и XML-документация — на русском языке; имена типов/методов/полей — на английском.

    Именование полей состояния¶

    Исторически сложившиеся поля-«рабочие переменные» класса SapfirDrafter:

    Поле Смысл
    appSpf, docSpf, projSpf, storeySpf приложение, документ, проект, этаж САПФИР
    paramModelSpf текущая параметрическая модель
    polylineSpf текущая осевая линия
    buf1 буфер object[] для обмена с COM
    selectedMaterialGuid выбранный GUID материала (на текущую команду)

    Новый код следует этим именам (<сущность>Spf).

    Работа с AutoCAD API¶

    • Любая работа с примитивами — внутри using (Transaction ...).
    • Примитивы, которым будет записан XData, открываются OpenMode.ForWrite.
    • Выбор — только через AcUtilites.Selection() (единый PickFirst-сценарий).
    • Итерация — через AcUtilites.ActionOn*, а не рукописные циклы в командах.
    • Сообщения — Editor.WriteMessage, формат: новая строка \n, два пробела, «Имя элемента ID={0}».

    Работа с COM САПФИР¶

    • Сначала ResolveActiveContext(), затем создание моделей.
    • Порядок операций для модели: NewModel → осевая линия/контур → параметры → материал → RegenModel() → SetSapfirId.
    • Числовые параметры приводите к double явно; массивы координат — object[] с чередованием x, y, z.
    • Исключения COM не должны «всплывать» в AutoCAD: перехватывайте и печатайте понятное сообщение, либо (как в Sapfir_WALL_EDIT) осознанно игнорируйте — но с комментарием.

    Обработка ошибок¶

    Практика Комментарий
    try/catch вокруг чтения параметров САПФИР параметр может отсутствовать → значение по умолчанию
    Пустой catch { } допустим только для «мягких» операций (обновление геометрии, сканирование материалов) и должен сопровождаться пояснением в отчёте/доке
    Отмена пользователем проверяйте PromptStatus.OK и молча выходите

    Документация¶

    • Исходники документации — в docs/ (markdown), конфигурация сайта — mkdocs.yml.
    • Новая команда → строка в таблице команд + страница в docs/commands/.
    • Локальные рабочие заметки держите в docs/superpowers/ — эта папка игнорируется git и исключена из сборки сайта.
    • Проверка сайта локально:
    python -m mkdocs serve      # http://127.0.0.1:8000
python -m mkdocs build      # результат в site/

    Git¶

    • Ветка разработки — master; коммиты прямо в неё (проект небольшой).
    • Сообщения коммитов — на английском, в императиве, первая строка до 72 символов, детали — списком в теле:
    Add unmarked axes option, reverse axis numbering

- AxesWizardForm: add rule 4 'Без маркировки'
- SapfirDrafter: axes display '(без маркировки)' for empty names
    • В репозиторий попадают только исходники и документация. Не коммитьте: bin/, obj/, site/, docs/superpowers/, AGENTS.md (см. .gitignore).
    • Публикация документации: python -m mkdocs gh-deploy --force (ветка gh-pages).

    Версионирование¶

    Версия сборки задаётся в Properties/AssemblyInfo.cs (AssemblyVersion, AssemblyFileVersion). При значимых изменениях обновляйте обе строки и указывайте версию в описании релиза.
